这是对所提供的电路优化代码逻辑的描述，从宏观到微观的优化流程和方法论：

### 优化逻辑描述（从大到小）

#### 1. 大循环/整体优化流程 (`run_full_optimization_flow`)

整个优化流程是一个**动态两阶段优化 (Dynamic Two-Stage Optimization)** 结构，旨在先严格满足电路的基本性能约束，然后尝试在满足约束的前提下进一步优化设计目标。

**主要阶段（Pass）:**

1.  **准备阶段 (Setup):**
    * 解析命令行参数，初始化Aether环境。
    * 读取初始参数并构建电路图 (`CircuitGraph`)，进行**对称性分析** (`analyze_circuit_constraints`)，以便在优化过程中成组地调整参数，确保设计对称性。
    * 运行基线仿真，获取归一化所需的初始性能指标 (`baseline_scores`)。
    * 准备**并行 MDE 视图**，以加速后续的仿真评估（I/O 管理优化）。
    * 初始化**候选解追踪器** (`candidate_info`)，用于记录那些*恰好*满足部分（3个）硬约束的解。

2.  **第一阶段优化 (Pass 1 - Strict):**
    * **目标函数:** 使用**严格评分函数** (`get_score`)，目标是尽快满足所有 4 个硬性约束（如相位裕度 $\text{PM} \ge 50^\circ$、直流增益 $\text{Gain} \ge 80\,\text{dB}$ 等）。
    * **迭代方法:** 使用**基于梯度的爬山法 (Gradient Descent / Hill Climbing)**，结合**贪婪跳跃 (Greedy Jump)** 和**参数冻结**机制。
    * **结果确认:** Pass 1 找到的最优解 (`pass1_tracking_info`)，以及过程中发现的最佳 3 约束候选解 (`candidate_info`)。

3.  **中场检查与决策 (Intermission Check):**
    * 检查 Pass 1 找到的全局最优解是否**满足所有 4 个约束**。
    * **决策逻辑:**
        * **情况 A:** 如果已完美满足所有约束或仿真预算耗尽，则**停止优化**。
        * **情况 B:** 如果未完美满足，但找到了一个**合格的 3 约束候选解** (`candidate_info` 非空)，则进入 Pass 2。
        * **情况 C:** 未完美满足，也未找到合格候选解，则**停止优化**（视为陷入困境）。

4.  **第二阶段优化 (Pass 2 - Relaxed, Optional):**
    * **起始点:** 从 Pass 1 找到的最佳**3 约束候选解**开始。
    * **目标函数:** 使用**灵活评分函数** (`get_score_flexible`)，将难以达到的直流增益目标（如 $80\,\text{dB}$）**放宽**到一个更容易达到的目标（如 $60\,\text{dB}$ 或基于候选解表现动态设定），然后在新约束下优化性能（Area vs UGB）。
    * **迭代方法:** 继承 Pass 1 的迭代方法。

5.  **结束阶段 (Finalize):**
    * 根据决策结果，确定**最终最优解** (`final_tracking_info`)。
    * 将结果（包括最终性能指标和参数值）打印到控制台，并写入最终结果文件。
    * 清理并行 MDE 视图。

#### 2. 单次优化阶段（Pass）的不同 Stage (`run_optimization_pass`)

每个优化阶段（Pass 1 或 Pass 2）内部都划分为两个**连续的 Stage**，以应对不同类型的参数：

1.  **阶段一：整数参数调整 (Stage 1: 'm' Parameter Tuning)**
    * **针对参数:** 仅针对离散值参数，通常是晶体管的乘法因子 (`_m` 参数)。
    * **迭代逻辑:** 核心是**随机顺序单参数爬山法**。
        * 随机选择一个**未冻结**的 `_m` 参数。
        * 尝试按**上次成功的方向**（如果有）或相反方向（$+1$ 或 $-1$）调整步长。
        * **贪婪跳跃 (Greedy Jump):** 如果新的探针解比当前解的分数**有显著改善**（超过设定的百分比阈值），则立即接受该新解并开始下一轮迭代（不对剩余参数进行探针）。
        * **参数冻结:** 如果一个参数尝试了两个方向都没有找到**比当前解更好的解**，则该参数被**冻结**，不再参与 Stage 1 的后续迭代。
        * **过渡条件:** 预算耗尽，或所有 `_m` 参数都被冻结。

2.  **阶段二：连续参数调整 (Stage 2: Continuous Parameter Tuning)**
    * **针对参数:** 针对连续值参数（如宽度 $\text{w}$、长度 $\text{l}$、电阻 $\text{r}$、电容 $\text{c}$ 等），即所有非 `_m` 参数。
    * **迭代逻辑:** 核心是**单参数爬山法，但没有贪婪跳跃**。
        * 随机选择一个**未冻结**的连续参数。
        * 尝试按**当前值的一定比例** (`perturb_ratio=0.10`) 增加或减少。
        * **迭代更新:** 在完成对**所有未冻结**连续参数的一轮探针后，将当前解更新为该轮中发现的**最佳邻居解**。
        * **参数冻结:** 如果一个参数尝试两个方向后，**在当前迭代中**没有找到比当前最佳解更好的解，则该参数被**冻结**，不再参与 Stage 2 的后续迭代。
        * **过渡条件:** 仿真预算耗尽，或一整轮迭代中所有参数都被冻结，或者一整轮迭代后未找到任何改善。

#### 3. 结果确认、迭代方法与过渡

* **结果确认:**
    * **局部最优:** 每个探针解 (`probe`) 的分数都会与该 Pass 中**全局追踪的最优解** (`tracking_info`) 进行比较。如果更好，则更新全局最优解，并立即保存到文件 (`best_params_so_far.txt`)。
    * **最终结果:** 在整个 `run_full_optimization_flow` 结束后，`final_tracking_info` 中记录的参数即为最终结果。

* **评分函数（目标函数）:**
    * 评分函数（`get_score` / `get_score_flexible`）是**带惩罚项的加权目标函数**。
    * **惩罚区（Violation Zone）:** 如果任何硬性约束（PM、Gain、GM、Iopa）被违反，则返回一个巨大的惩罚值 $\left(10^9 + \text{Total\_Violation} \times 10^6\right)$，目标是**最小化惩罚项**。
    * **目标区（Goal Zone）:** 一旦所有约束都满足（惩罚为 0），分数转变为**归一化加权和** $\left(0.5 \times \text{Area}_{\text{norm}} - 0.5 \times \text{UGB}_{\text{norm}}\right)$，目标是**减小面积** ($\text{Area}_{\text{norm}}$) 并**增大单位增益带宽** ($\text{UGB}_{\text{norm}}$)。

* **迭代方法:**
    * **方法:** 核心使用的是**单参数局部搜索/爬山法 (Local Search / Hill Climbing)**，而不是传统的梯度下降。它每次只尝试改变一个参数，并评估结果。
    * **步长:** `_m` 参数的步长是离散的 $\pm 1$；连续参数的步长是相对的 $\pm 10\%$ (`perturb_ratio`)。
    * **方向记忆:** 使用 `last_success_direction` 记录每个参数上次成功移动的方向，以便在下一次迭代中**优先尝试**该方向。
    * **贪婪性:** Stage 1 引入的**贪婪跳跃**允许优化器在发现明显更好的解时立即采纳，加快在**惩罚区**的搜索速度。
